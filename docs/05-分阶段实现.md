# 伴办 · 分阶段实现与代码地图

| 项目 | 内容 |
| --- | --- |
| 交付形态 | 一次性交付到 Phase 3 的完整 MVP；下面按阶段给出可独立验收的代码切片 |
| 总工期估算 | 单人 10–13 个工作日（设计 2 + 核心 3 + 时间能力 4 + 打磨 3） |
| 当前状态 | Phase 0–3 已完成；Phase 4 不在本次范围 |
| 测试 | 单元测试 + Edge CDP 端到端，全部通过 |

> 说明：本仓库不是三个割裂的版本，而是同一个可运行应用。每一阶段都能在 `js/`、`docs/` 中找到对应实现，并可按“阶段验收”单独演示。若需要按阶段交付给不同人，可按文件/函数边界拆分支。

## 2. Phase 0 · 设计与骨架

### 目标

先把“看起来是什么、怎么导航、数据放哪”定下来，避免边写页面边改结构。

### 交付物

| 交付 | 位置 |
| --- | --- |
| 设计 token：暖纸色、墨绿、四类型色、字体、圆角、阴影 | `assets/app.css` 顶部 `:root` |
| 应用壳、底部导航、悬浮加号 | `index.html` + `.tabbar` |
| 内联图标库（24 个，含四类型） | `js/ui.js` 的 `PATHS` |
| PWA Manifest | `manifest.webmanifest` |
| 应用图标（192/512/maskable/apple） | `assets/icons/*`，生成脚本 `tools/make_icons.py` |
| 示例任务 8 条、首次 seed 逻辑 | `js/store.js` 的 `seedTasks()` |
| 页面与数据文档 | `docs/01`–`docs/04` |

### 代码切片

- 只打开 `index.html` 时，即使 JS 还没写，也能看到导航和背景；Phase 0 不依赖数据层。
- 图标全部内联 SVG，避免网络请求；应用图标用 Pillow 4× 超采样生成，边缘平滑。
- 示例数据围绕“今天”相对生成，保证任何日期打开都有内容可看。

### 阶段验收

- [x] 360px 宽度下导航不溢出，中央加号不挡 Tab 文案。
- [x] 图标在 192/512/maskable 三种用途下不裁切主体。
- [x] 设计 token 用 CSS 变量统一，四类色可一处调整。
- [x] Manifest 可被浏览器识别（名称、主题色、图标）。

## 3. Phase 1 · 记录闭环

> 这一阶段的目标是：**打开 App → 说一句话 → 存下来 → 能在列表和详情看到 → 能改能删**。先不追求复杂提醒。

### 目标

- 本地任务能持久化；
- 自然语言能拆出标题、时间、优先级、标签；
- 今日 / 收件箱 / 详情能跑通；
- 新建和编辑共用同一个弹层。

### 交付物与代码

| 能力 | 代码位置 | 说明 |
| --- | --- | --- |
| 日期/格式化工具 | `js/util.js` | `startOfDay`、`formatDate`、`formatRemaining`、`escapeHTML` |
| 任务 Schema / 标准化 | `js/store.js` `normalizeTask()` | 所有输入的唯一出口 |
| localStorage 读写 | `js/store.js` `load()` / `save()` | 版本、损坏备份 |
| 示例数据 | `js/store.js` `seedTasks()` | 8 条，覆盖四类型 |
| 解析器 v1 | `js/parser.js` `parse()` | 标签/优先级/日期/时间/标题 |
| 任务卡与类型徽章 | `js/ui.js` `taskCard()` | 四类色、倒计时、标签 |
| 今日页 | `js/app.js` `pageToday()` | 分组、焦点卡、已完成 |
| 收件箱 | `js/app.js` `pageInbox()` | 类型/状态/标签/排序 |
| 详情基础 | `js/app.js` `pageTaskDetail()` | 元信息、备注、完成、删除、编辑 |
| 新建/编辑弹层 | `js/app.js` `openComposer()` / `composerHTML()` / `saveTask()` | 实时解析、字段可改 |
| 搜索基础 | `js/app.js` `pageSearch()` | 关键词 + 类型 |
| 路由 | `js/app.js` `parseRoute()` | Hash 路由 |
| 事件 | `js/app.js` `onClick()` / `onInput()` / `onChange()` | 事件委托 |

### 关键实现顺序（建议按此顺序读代码）

1. `store.js`：先定义 Task 长什么样，再写 seed。
2. `util.js`：日期与格式化。
3. `parser.js`：从“明天/周五/下午3点”开始，逐步加重复/标签。
4. `ui.js`：先做任务卡，四类型视觉差异在这里落地。
5. `app.js`：先今日 → 详情 → 新建，最后收件箱/搜索。
6. `app.css`：先布局，再卡片，再弹层。

### 阶段验收

- [x] 首次打开有 8 条示例，刷新后仍在。
- [x] “明天下午3点交高数作业 #作业 紧急”能保存为限时/高优/明天15:00/标签作业。
- [x] “买牛奶”保存为无日期普通任务。
- [x] 今日页、收件箱、详情三处数据一致。
- [x] 编辑标题/日期/优先级后，列表立即更新。
- [x] 删除有确认，删除后回到列表。
- [x] 360px 无横向溢出。

### 演示脚本

1. 打开今日 → 点“告诉伴办”。
2. 输入上面那句话 → 看识别结果 → 改优先级为“中” → 保存。
3. 回今日看到新任务；进详情改标题；返回。
4. 在收件箱按“限时”筛选，确认能找到。
5. 刷新页面，任务还在。

## 4. Phase 2 · 时间能力

> 这一阶段让“时间”真正有用：日历能看到，倒计时会走，定期会自动续，提醒会分级。

### 目标

- 月历与选中日；
- 重复规则与下一次生成；
- 截止前 24h/3h/30min / 逾期重复；
- 设置页可开关提醒、切换周起始日；
- 系统通知权限流程。

### 交付物与代码

| 能力 | 代码位置 | 说明 |
| --- | --- | --- |
| 重复规则计算 | `js/util.js` `nextOccurrence()` | 日/周/月/年、间隔、月末截断 |
| 重复描述 | `js/util.js` `describeRecurrence()` | 每周一、三、五 · 07:30 |
| 定期任务自动续 | `js/store.js` `completeTask()` | 克隆下一次、`nextTaskId`、恢复撤回 |
| 月历 | `js/app.js` `pageCalendar()` | 42 格、类型点、今天/选中态 |
| 日历手势 | `js/app.js` `bindCalendarSwipe()` | 44px 阈值 |
| 倒计时 | `js/app.js` `tickClock()` / `updateCountdowns()` | 卡片/焦点/详情 |
| 提醒计划 | `js/notify.js` `collect()` | 按任务生成事件、去重 |
| 通知投递 | `js/notify.js` `deliver()` | 前后台分流 |
| 逾期强提醒 | `js/notify.js` `overdueEvent()` | 按分钟分桶 |
| 权限/测试 | `js/notify.js` `requestPermission()` / `test()` | 用户手势触发 |
| 设置页提醒区 | `js/app.js` `pageSettings()` | 开关、间隔、简报 |
| Service Worker | `sw.js` | 缓存 + 通知点击 |
| PWA 清单 | `manifest.webmanifest` | 安装、图标、快捷方式 |

### 关键实现顺序

1. `nextOccurrence()` + 单元测试：先把重复算对。
2. `completeTask()`：定期任务“完成 → 下一次”。
3. `pageCalendar()`：只读展示，再接点选/滑动。
4. `notify.collect()`：纯函数 + 账本去重，先不碰系统 API。
5. `app.js` 提醒循环：每次最多一条，避免轰炸。
6. `sw.js` + 权限 UI：最后接系统通知。
7. 设置项：先开关，再持久化。

### 阶段验收

- [x] 周一三五任务完成后，下一次落在下一个周一/三/五。
- [x] 逾期完成不会补生成一串过期任务。
- [x] 2 小时后截止的任务只触发 3 小时档，不会再触发 24 小时档。
- [x] 逾期 10 分钟后再次提醒（间隔可设）。
- [x] 日历点选日期、切换月份、滑动切月正常。
- [x] 周起始日切换后，日历列顺序变化。
- [x] 关闭 30 分钟档后，不再收到该档提醒。
- [x] 页面隐藏且已授权时使用系统通知；页面可见时只显示 Toast。

### 演示脚本

1. 新建“30分钟后交实验报告” → 详情看倒计时。
2. 完成“每天背单词” → 看“下一次已生成”，回今日能看到下一次。
3. 日历切到下周 → 点某天 → 添加 → 保存。
4. 设置里关闭“提前 24 小时” → 新建明天任务，确认不会收到 24h 档（可在 debug 时间/单元测试验证）。
5. 开启通知 → 点“测试” → 看系统通知（HTTPS 或 localhost）。

## 6. Phase 4 · 原生增强（不在 MVP）

### 何时进入

当出现以下信号之一：

- 用户反馈“关掉浏览器后没收到提醒”成为主要投诉；
- 需要系统日历同步；
- 需要后台可靠提醒/小组件/锁屏实时活动。

### 方案

| 项 | 方案 |
| --- | --- |
| 壳 | Capacitor（iOS/Android），复用现有 Web 代码 |
| 本地通知 | `@capacitor/local-notifications`，按任务 dueAt 排程 |
| 通知重排 | 任务增删改/完成时重建该任务的本地通知 |
| 系统日历 | iOS EventKit / Android CalendarContract 插件 |
| 数据 | 继续本地优先；可选 iCloud/Google Drive 备份（仍无自建后台） |
| 发布 | App Store / Google Play |

### 迁移注意

- Web 端 `notify.js` 抽象出 `schedule/cancel` 接口，原生壳实现同名接口；
- `dueAt` 仍是 ISO；原生排程按本地时区转换；
- 保留 PWA 作为免安装体验；
- 隐私说明更新：若接云备份，必须明确告知。

## 10. 下一步建议（按优先级）

1. **真机验证通知**：iPhone 添加到主屏幕 + Android Chrome，记录各机型行为；不达标就进入 Phase 4。
2. **解析器语料扩充**：收集 100 条真实学生输入，做成回归集；优先修“时间歧义”和“标题清理”。
3. **列表性能**：任务 >300 条后引入虚拟列表或分页。
4. **深色模式**：现有 CSS 变量已具备条件，补一组暗色 token 即可。
5. **系统日历同步**：先做“导出 .ics”，成本低；再做原生双向同步。
