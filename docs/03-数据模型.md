# 伴办 · 数据模型与本地存储

| 项目 | 内容 |
| --- | --- |
| 存储介质 | `localStorage`（单用户、单设备） |
| 主键 | `banban.state.v1` |
| Schema 版本 | `1` |
| 数据量预期 | 1000 条任务以内；单任务备注 ≤ 2000 字 |
| 迁移 | 读取时 `migrate()`，未来版本递增 `version` |

---

## 1. 存储结构

```ts
interface AppState {
  version: 1;
  tasks: Task[];
  settings: Settings;
  meta: Meta;
}

interface Settings {
  weekStart: 0 | 1;                 // 0=周日，1=周一
  reminders: {
    h24: boolean;                   // 提前 24 小时
    h3: boolean;                    // 提前 3 小时
    m30: boolean;                   // 提前 30 分钟
    overdueRepeatMin: 5 | 10 | 30 | 60;
  };
  digest: boolean;                  // 每日简报
  digestTime: string;               // "08:00"
  reduceMotion: boolean;
  notificationsAsked: boolean;      // 是否已经主动询问/关闭过通知引导
  defaultTime: string;              // 预留：默认时刻，当前由解析器固定 20:00
}

interface Meta {
  createdAt: string;                // ISO
  seeded: boolean;                  // 是否已写入过示例，避免清空后重新灌入
  digestDate: string;               // 最近一次每日简报的 YYYY-MM-DD
  demoBannerDismissed: boolean;     // 今日页示例提示是否已关闭
}
```

**为什么是一个 key？**

- 数据规模小，单次读写简单；
- 便于整体导出/导入和版本迁移；
- 避免多 key 写入一半造成不一致；
- 写满时一次性失败，可明确提示导出。

## 2. Task

```ts
type TaskType = 'deadline' | 'recurring' | 'longterm' | 'normal';
type TaskStatus = 'active' | 'done';
type Priority = 'high' | 'medium' | 'low';

interface Task {
  id: string;                       // task_xxx
  title: string;                    // 1–120 字
  notes: string;                    // 0–2000 字
  type: TaskType;
  status: TaskStatus;
  priority: Priority;

  dueAt: string | null;             // ISO；null = 无日期
  hasTime: boolean;                 // false 表示只显示日期，实际时间落在 23:59
  startAt: string | null;           // 时间段任务的开始时间

  recurrence: Recurrence | null;
  seriesId: string | null;          // 同一重复系列共享
  occurrenceIndex: number;          // 第几次，从 0 开始

  progress: number;                 // 0–100；长期任务有阶段时为派生值
  milestones: Milestone[];

  tags: string[];                   // 最多 8 个，不含 #
  sourceText: string;               // 用户原话，≤500 字
  parseMeta: ParseMeta | null;      // 解析快照
  remindersSent: Record<string, string>; // key → 发送时间 ISO
  nextTaskId: string | null;        // 定期任务完成后指向下一次

  demo: boolean;                    // 示例数据标记
  createdAt: string;
  updatedAt: string;
  completedAt: string | null;
}
```

### 2.1 字段约束

| 字段 | 约束 | 兜底 |
| --- | --- | --- |
| `title` | trim；空则“未命名任务”；最多 120 字 | “未命名任务” |
| `notes` | 最多 2000 字 | `""` |
| `type` | 四个枚举之一 | `normal` |
| `priority` | 三个枚举之一 | `medium` |
| `dueAt` | 合法 ISO；无效置 null | `null` |
| `recurrence` | 合法对象；有 recurrence 时 type 强制 `recurring` | `null` |
| `tags` | 去 `#`、去重、最多 8 个 | `[]` |
| `progress` | 0–100 整数 | `0` |
| `status` | `active` / `done` | `active` |
| `createdAt` | 合法 ISO | 当前时间 |
| `completedAt` | done 时自动补当前时间 | `null` |

### 2.2 派生规则

1. **类型的展示优先级**：`recurrence != null` → 定期；否则使用 `type`。
2. **长期进度**：
   - 有阶段：`round(doneMilestones / totalMilestones * 100)`；
   - 无阶段：用户手动维护的 `progress`；
   - `status === 'done'`：强制 100。
3. **卡片倒计时**：所有有 `dueAt` 的 active 任务都计算；限时/定期/长期的目标日都会显示。
4. **颜色/图标**：不存储，从 `type` 派生（避免数据与视觉耦合）。
5. **系列关系**：`seriesId` 在首次创建定期任务时生成；克隆下一次时沿用。

## 3. 重复规则

```ts
interface Recurrence {
  freq: 'daily' | 'weekly' | 'monthly' | 'yearly';
  interval: number;                 // ≥1；每 N 天/周/月/年
  weekdays: number[];               // 0=周日 … 6=周六；weekly 使用
  monthDay: number | null;          // 1–31；monthly/yearly 使用
  month: number | null;             // 1–12；yearly 使用
  time: string;                     // "HH:MM"
  anchor: string | null;            // ISO，周期相位锚点
}
```

### 3.1 生成规则

- **每天**：从 anchor 所在日期起，每 `interval` 天的 `time`。
- **每周**：
  - 指定 `weekdays` 时，按周迭代；`interval > 1` 时以 anchor 所在周为第 0 周，每 N 周才允许出现。
  - 未指定星期时，使用 anchor 的星期。
  - 周一作为内部周起点；周日映射为偏移 6。
- **每月**：按 `monthDay`（缺省 anchor 的日）；遇到当月天数不足时截断（31 号 → 2 月 28/29 号）。
- **每年**：按 `month` + `monthDay`；2 月 29 日会截断到 28 日。
- **严格晚于基准时间**：所有 `nextOccurrence(rec, after, anchor)` 返回 `> after` 的第一个时间点。

### 3.2 首次与下一次

```text
首次：nextOccurrence(rec, now - 1s, baseDate)
完成：nextOccurrence(rec, max(dueAt, now - 1min), anchor)
```

- 首次：用户可能选了一个已过去的日期，这时自动排到下一个周期。
- 完成：
  - 提前完成：从本次 dueAt 之后算，不会把同一天下一时段提前生成；
  - 逾期完成：从当前时间之后算，跳过已经错过的多次，避免一连串“补作业”。

### 3.3 示例

| 规则 | anchor | 下一次 |
| --- | --- | --- |
| `daily / 1 / 07:30` | 2026-11-20 18:00 | 2026-11-21 07:30 |
| `weekly / 1 / [1,3,5] / 07:30` | 2026-11-20 周五 | 2026-11-23 周一 07:30 |
| `weekly / 2 / [1] / 20:00` | 2026-11-23 周一 | 之后 2026-12-07 周一 |
| `monthly / 1 / day 31 / 20:00` | 2026-01-31 | 2026-02-28 20:00 |
| `yearly / 1 / 3-05 / 20:00` | 2026-11-20 | 2027-03-05 20:00 |

## 4. 阶段与解析快照

```ts
interface Milestone {
  id: string;                       // ms_xxx
  title: string;                    // ≤80 字
  dueAt: string | null;             // ISO
  done: boolean;
  doneAt: string | null;
}

interface ParseMeta {
  confidence: number;               // 0–1
  matches: Array<{
    field: 'due' | 'start' | 'recurrence' | 'priority' | 'tags' | 'type';
    text: string;
    label: string;
  }>;
  warnings: string[];
  parsedAt: string;
}
```

- 阶段没有 `hasTime` 字段；详情展示时若 `HH:mm === "23:59"` 则不显示时间，否则显示时间。
- `ParseMeta` 只是“来源说明”，不参与业务计算；任务编辑后仍保留，除非重新识别。

## 5. 提醒账本

```ts
remindersSent: {
  "lead:h3:2026-11-21T07:00:00.000Z": "2026-11-20T18:30:00.000Z",
  "overdue:2026-11-20T15:00:00.000Z:12": "2026-11-20T17:30:00.000Z",
  "ms-soon:ms_ab12:2026-11-22T12:00:00.000Z": "2026-11-21T12:00:00.000Z"
}
```

| 前缀 | 含义 | 说明 |
| --- | --- | --- |
| `lead:h24:<dueISO>` | 提前 24h | 每档独立 key |
| `lead:h3:<dueISO>` | 提前 3h | 每档独立 key |
| `lead:m30:<dueISO>` | 提前 30min | 每档独立 key |
| `overdue:<dueISO>:<bucket>` | 逾期重复 | bucket = floor(逾期毫秒 / 间隔) |
| `ms-soon:<msId>:<dueISO>` | 阶段前 24h | 每阶段一次 |
| `ms-now:<msId>:<dueISO>` | 阶段到期 | 每阶段一次 |

- 修改 `dueAt` 会重置该任务的 `remindersSent`（在保存时比较 dueAt 与 recurrence 是否变化）。
- 账本最多保留 120 个 key，超过时按发送时间删除最旧的 40 个。
- 每日简报不写任务账本，写在 `meta.digestDate`。

## 6. 存储生命周期

### 6.1 首次启动

```
localStorage 无 key
  → 生成 8 条示例任务（相对当前时间）
  → settings 默认值
  → meta.seeded = true
  → save
```

示例任务覆盖：2 条今天截止、1 条明天截止、1 条每日重复、1 条长期带 4 个阶段、2 条普通、1 条已完成。
只用于演示，设置里可一键清空，不会在清空后自动回灌（`meta.seeded` 已为 true）。

### 6.2 读取与迁移

```ts
load():
  raw = localStorage.getItem(KEY)
  if (!raw) → initialState + save
  parse JSON
  migrate():
    normalize each task
    merge settings with defaults
    merge meta with defaults
  if (error) → 备份 raw 到 KEY + ".broken" → initialState + save
```

`migrate()` 是“宽进严出”：字段缺失用默认值，非法值回退，保证旧版本/手工改坏的数据尽量可打开。

### 6.3 写入

- 每次创建/更新/完成/删除/设置变化后整体序列化写入。
- 写入失败（配额/隐私模式）返回 `{ ok: false, error }`；UI 提示“本地存储空间不足，建议先导出备份”，不静默丢失。
- 跨标签页同步：监听 `storage` 事件重新 `load()` 并渲染。

### 6.4 删除

- 物理删除任务；没有回收站。
- 定期任务恢复时，如果下一次是自动生成且仍 active，则一并删除。
- 危险操作均有确认弹层。

## 7. 导入 / 导出格式

```json
{
  "app": "伴办",
  "schema": 1,
  "exportedAt": "2026-11-20T10:30:00.000Z",
  "tasks": [ ...Task ],
  "settings": { ...Settings }
}
```

**导入策略**

1. 解析 JSON；
2. 必须有 `tasks` 数组；
3. 逐条 `normalizeTask`，丢弃无法识别的空对象；
4. 设置与默认值合并，缺省项保留默认；
5. 二次确认后**整体覆盖**当前任务与设置；
6. 导入后写回本地存储。

**不做**：增量合并、去重、冲突解决。MVP 以“整机备份恢复”为目标，避免产生半合并状态。

## 9. 数据一致性检查清单

- [x] 有 `recurrence` 一定有 `type=recurring`，且 `dueAt` 不为空。
- [x] 定期任务的 `seriesId` 不为空。
- [x] `status=done` 时 `completedAt` 不为空。
- [x] 长期任务 `progress` 与阶段完成数一致（有阶段时）。
- [x] `tags` 无 `#`、无重复、最多 8 个。
- [x] `dueAt` 非法时回退 null，不抛异常。
- [x] 导入的最小数据（只有 title）可以标准化成完整任务。
- [x] 写入失败不会清空旧数据。
