# 伴办 · 需求文档（MVP）

| 项目 | 内容 |
| --- | --- |
| 产品名 | 伴办 |
| 一句话 | 用大白话记待办，自动排好时间、优先级和提醒的手机日历备忘录。 |
| 版本 | v0.9.0 · MVP |
| 文档日期 | 2026-11-20 |
| 端形态 | 仅手机端，移动优先 PWA；不做桌面端、社交、复杂后台 |
| 数据策略 | 单用户、本地优先、无账号、无云端同步 |

---

## 1. 背景与问题

大学生的任务有几个典型特征：

1. **来源杂**：课程作业、小组汇报、考试、社团、实习、生活琐事混在一起。
2. **时间形态多**：有硬截止的实验报告、每天背单词、持续一个月的毕设、没有明确时间的“有空去还书”。
3. **记录成本高**：打开日历 App 建任务，要填标题、选日期、选时间、选分类、设提醒，五六步之后就懒得记了。
4. **害怕漏掉**：作业和 DDL 集中在晚上；普通备忘录不会倒计时，也不会在截止前反复提醒。

伴办要解决的不是“更复杂的项目管理”，而是：**让记任务这件事足够快，同时让不同类型的任务都被正确地提醒和呈现。**

## 2. 目标与非目标

### 2.1 MVP 目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 一句话创建任务 | 从打开输入框到保存 ≤ 2 次主要操作；解析后字段可直接修改 |
| G2 | 四类任务差异化 | 限时、定期、长期、普通在颜色、图标、卡片信息、详情操作上均有区别 |
| G3 | 不漏掉硬截止 | 截止前 24h / 3h / 30min 分级提醒；逾期后按设置重复强提醒 |
| G4 | 定期任务不断档 | 完成本次后自动生成下一次，并保留系列关系 |
| G5 | 长期任务可推进 | 支持总进度、阶段清单、阶段截止和阶段提醒 |
| G6 | 手机离线可用 | 断网仍可打开、增删改查；数据只在本机 |
| G7 | 五分钟能验收 | 首次打开有示例数据，所有页面可点、可改、可删 |

### 2.2 明确不做（MVP）

- 桌面端适配、多端同步、账号体系。
- 好友、班级、群组、任务指派等社交能力。
- 后台服务、云数据库、推送服务器。
- 复杂项目管理：甘特图、依赖关系、子任务无限层级、工时。
- 独立笔记库：备忘录能力落在每条任务的“备注”里，不单独做一篇篇笔记的管理器。
- AI 云端大模型调用；MVP 的自然语言解析完全本地规则化，离线可用。
- 日历双向同步（系统日历 / Google Calendar / Outlook）。
- 应用内购买、会员、广告。

## 3. 用户与场景

### 3.1 目标用户

**林同学，大三，信息类专业。**

- 同时有 4 门课、1 个小组项目、1 个毕设方向、社团和实习投递。
- 每天用手机最多，电脑不总在身边。
- 用过系统备忘录和日历，但觉得“记下来”和“被提醒”是两件事。
- 接受新工具的前提：**不要让我填表**。

### 3.2 核心场景（JTBD）

| 场景 | 用户心里的话 | 伴办应该做什么 |
| --- | --- | --- |
| 课上突然布置作业 | “下周三前交，别忘了” | 一句话识别“下周三前”，生成限时任务，自动设截止与提醒 |
| 每天习惯 | “每天背 50 个单词” | 识别每天 07:30，生成定期任务；完成一次自动续下一天 |
| 毕设 | “开题报告要写一个月，分几个阶段” | 生成长期任务，建阶段，按阶段提醒，进度可视化 |
| 碎片想法 | “有空把书还了” | 生成普通任务，不制造假截止，放进收件箱/随时可做 |
| 临时找任务 | “上次那个实验报告叫什么来着” | 按标题、标签、备注搜索，按类型/优先级/状态筛选 |
| 已经逾期 | “坏了，昨天就该交” | 红色逾期标记、倒计时变逾期时长、强提醒重复出现 |

## 4. 任务模型

### 4.1 四种任务类型

| 类型 | 颜色 | 图标 | 何时使用 | 卡片上显示 | 详情额外能力 |
| --- | --- | --- | --- | --- | --- |
| 限时 | 珊瑚红 `#D9553F` | 沙漏 | 有明确截止时间的作业、报名、提交、会议 | 截止时间、倒计时、逾期强调 | 大倒计时、截止进度、分级提醒 |
| 定期 | 蓝 `#3568D4` | 循环箭头 | 每天/每周/每月重复的打卡、课程、习惯 | 重复规则、距本次截止倒计时 | 完成本次后生成下一次、系列关系 |
| 长期 | 紫 `#7151C9` | 同心圆靶 | 毕设、论文、备考、项目、课程设计 | 总进度、阶段数、目标日 | 进度条、阶段清单、阶段提醒、手动调进度 |
| 普通 | 绿 `#2F7D63` | 勾选方框 | 没有明确时间的生活琐事、想法 | “随时可做”或无日期 | 不强制时间，可随时补日期 |

> 颜色之外必须同时有**图标 + 文字标签**，避免只靠颜色区分；任务卡左侧色轨仅作辅助。

### 4.2 优先级

- 高：红色/珊瑚色“高优”标签，列表优先展示。
- 中：默认，不显示标签，保持界面安静。
- 低：灰色“低优”标签。

### 4.3 状态

- `active`：进行中。
- `done`：已完成；有完成时间，可在“今天已完成”折叠区/收件箱已完成中查看。
- 删除是物理删除；危险操作有确认弹层。

## 5. 功能需求

### F1 智能捕获（P0，核心）

**入口**

- 今日页顶部“告诉伴办你要做什么”。
- 底部导航中央“+”。
- 日历某一天的“添加”。
- 空状态里的“记一件事”。

**流程**

1. 用户输入一句自然语言。
2. 输入停顿约 650ms 自动解析，也可点“重新识别”。
3. 页面展示识别结果：类型、日期时间、优先级、重复、标签。
4. 表单字段同步填充，全部可手动修改：
   - 标题、备注、类型、日期、时间、优先级、重复规则、星期、标签。
5. 保存后写入本地存储，回到来源页面并给出轻提示。

**必须支持的表达（MVP 范围）**

| 维度 | 支持示例 | 说明 |
| --- | --- | --- |
| 相对日 | 今天、明天、后天、大后天、今晚、明早 | “今晚”按 20:00，“明早”按 08:00 |
| 绝对日 | 11月25日、2026-11-25、12/5、下个月5号、月底 | 未写年份时按合理年份推断 |
| 星期 | 周五、下周三、本周五、周末 | 没写“这/下”的星期，若今天已过则排到下一次 |
| 时刻 | 15:00、下午3点、晚上八点半、23:00 前 | 中文数字、半/一刻/三刻 |
| 时间段 | 9:00-11:00、周六下午2点到4点 | 开始时间和截止时间都保存 |
| 相对时长 | 30分钟后、2小时后、3天后 | 以当前时间为基准 |
| 重复 | 每天、每个工作日、每周一三五、每周一、三、五、每月5号、每年3月5日、每两周周一、每个周末 | 支持间隔 |
| 优先级 | 紧急、重要、高优、优先、尽快 / 不急、有空、低优 | 默认中 |
| 标签 | `#作业`、`【高数】`、`标签：英语,习惯` | 最多 8 个 |
| 长期 | 长期、毕设、毕业设计、论文、项目、备考、课程设计、大作业、写论文 | 结合截止远近与进度词判断 |

**解析后处理规则**

- 标题会去掉已识别的时间、优先级、标签等片段。
- 只有日期、没有时刻 → 截止时间落在当天 23:59，但界面只显示日期（不制造“23:59”的假精确）。
- 定期任务没有写时间 → 默认 20:00，并在解析提示里说明。
- 只写了一个已过去的时刻且没有指定日期 → 顺延到明天同一时间。
- 只写“周五 9 点”且今天正是周五、9 点已过 → 排到下周五。
- 解析失败/信息不足时不阻塞创建：标题兜底为“未命名任务”，所有字段可手填。

**验收标准**

- [ ] 输入“明天下午3点交高数作业 #作业 紧急”，生成限时任务，标题“交高数作业”，明天 15:00，高优，标签“作业”。
- [ ] 输入“每周一三五早上7点背单词”，生成定期任务，每周一/三/五 07:00。
- [ ] 输入“12月20日截止 毕业设计 长期 进度”，生成长期任务，目标日 12月20日，标题“毕业设计”。
- [ ] 输入“30分钟后提醒我交实验报告”，30 分钟后截止。
- [ ] 输入“买牛奶”，生成无日期普通任务。
- [ ] 解析结果中每一个字段都能在保存前手动修改。

### F2 今日（P0）

**内容**

- 日期、问候语、今日待办数量、逾期数量、已完成数量。
- 一句话创建入口。
- 权限开启提示（仅首次/未决定时）。
- 示例数据提示（仅示例存在时）。
- “UP NEXT”焦点卡：最近一个 48 小时内的截止/逾期任务，含实时倒计时和完成按钮。
- 分组列表：已逾期、今天、接下来 7 天、长期任务、随时可做。
- 今日已完成折叠区。
- 首次无数据时的空状态。

**交互**

- 点卡片进入详情；点圆圈直接完成/恢复。
- 长按/滑动不做额外隐藏操作，避免学习成本。
- 倒计时每秒刷新；跨越截止时自动切换为逾期态并重排。

**验收标准**

- [ ] 今日页只显示 active 任务（已完成在折叠区）。
- [ ] 逾期任务永远排在今天任务之前，并有红色强调。
- [ ] 完成一个任务后，今日计数和分组实时更新。
- [ ] 点圆圈完成时不会误触进入详情。

### F3 日历（P0）

**内容**

- 月份切换（左右箭头 + 手势滑动）。
- 周一/周日开始的偏好。
- 月网格，日期下用类型色点标记。
- 选中日期高亮，今天有描边。
- 下方展示选中日的任务和长期阶段。
- “添加”按钮带入选中的日期。

**验收标准**

- [ ] 月份切换后日期网格正确，跨月日期淡化。
- [ ] 有任务的日期显示最多 3 个类型点；同类型只显示一个点。
- [ ] 点选日期后下方列表更新。
- [ ] 从某天添加，创建弹层默认带那一天，类型为限时。

### F4 收件箱（P0）

**内容**

- 搜索入口。
- 类型筛选：全部 / 限时 / 定期 / 长期 / 普通。
- 状态筛选：进行中 / 已完成 / 全部。
- 排序：按截止 / 按优先级 / 最近创建。
- 标签筛选。
- 按时间分组：已逾期 / 今天 / 接下来 7 天 / 以后 / 没有日期 / 已完成。

**验收标准**

- [ ] 所有任务都能在收件箱找到，包括无日期的普通任务。
- [ ] 多个筛选条件可叠加。
- [ ] 清除筛选恢复默认状态。
- [ ] 空结果有明确空状态与恢复入口。

### F5 任务详情与四类任务（P0）

**通用**

- 类型、标题、优先级、时间、重复、标签、备注。
- 倒计时 / 进度。
- 编辑、完成/恢复、删除（二次确认）。
- 来源原话与解析结果（如果由一句话创建）。
- 创建/更新时间。

**限时**

- 大号倒计时；逾期后变红并显示逾期时长。
- 截止进度条。
- 截止前 24h / 3h / 30min 分级提醒，逾期强提醒。

**定期**

- 重复规则、下次时间。
- 完成本次后：当前记录标记完成，同时生成下一次任务；显示“下一次已生成”。
- 恢复已完成本次时，若下一次是当前自动生成的且未完成，则一并撤回。

**长期**

- 总进度（有阶段时按已完成阶段自动计算；无阶段时可手动拖动）。
- 阶段清单：名称、截止、完成勾选、删除。
- 添加阶段。
- 阶段到期前 24h 与到期时提醒。
- 完成长期任务时，未完成阶段一并标记为完成，保证进度一致。

**普通**

- 不强制时间；无日期时显示“随时可做”。
- 可手动补日期，但类型保留为普通（用户可自行改限时）。

**验收标准**

- [ ] 四种类型在详情头部有不同颜色和图标。
- [ ] 定期任务完成后自动生成下一次，且下一次时间正确。
- [ ] 长期任务完成一个阶段，进度按阶段数自动更新。
- [ ] 删除任务有确认，删除后回到合理页面。

### F6 搜索筛选（P0）

**内容**

- 全屏搜索页，顶部返回 + 搜索框。
- 搜索范围：标题、备注、标签、来源原话。
- 筛选：类型、优先级、标签、状态。
- 结果计数、关键词高亮。
- 空结果提示。

**验收标准**

- [ ] 输入关键词即时过滤，无需回车。
- [ ] 搜索“论文”能命中标题/备注/标签中包含该词的任务。
- [ ] 筛选与关键词可叠加。
- [ ] 从搜索结果进入详情再返回，搜索词与筛选保留。

### F7 设置与通知（P0）

**通知设置**

- 系统通知权限状态：未开启 / 已开启 / 已关闭 / 不支持。
- 开启按钮、测试通知。
- 分级提醒开关：24h、3h、30min。
- 逾期强提醒间隔：5 / 10 / 30 / 60 分钟。
- 每日简报开关与时间（可选）。
- 阶段提醒说明。

**其他设置**

- 每周起始日。
- 减少动效。
- 数据导出/导入/载入示例/清空。
- 关于与隐私说明。

**验收标准**

- [ ] 权限请求必须由用户点击触发。
- [ ] 权限被拒绝时有解释文案，而不是静默失败。
- [ ] 关闭某一档提醒后，该档不再触发。
- [ ] 提醒在页面可见时以应用内 toast 呈现；页面隐藏且已授权时以系统通知呈现。

- localStorage 单键持久化，版本化。
- 首次无数据时写入 8 条示例任务（可直接清空）。

## 6. 提醒规则

### 6.1 截止前分级

| 档位 | 触发条件 | 通知表现 |
| --- | --- | --- |
| 24 小时 | 距截止 ≤ 24h，且未发送过 24h 档 | “还剩 X 小时/天 · 标题” |
| 3 小时 | 距截止 ≤ 3h，且未发送过 3h 档 | “还剩 X 小时 · 标题” |
| 30 分钟 | 距截止 ≤ 30min，且未发送过 30min 档 | “还剩 X 分钟 · 标题”，要求驻留 |
| 逾期 | 超过截止时间 | “已逾期 X · 标题”，红色强提醒；每 N 分钟重复 |

- 同一任务同一时刻最多触发一条，优先最紧迫档位；已经发过更紧迫档位时，不补发更早档位。
- 应用打开时只处理一条提醒，避免一次弹出一串通知。
- 应用在前台且通知已开启时用应用内 toast；页面隐藏时用系统通知。两者都不会重复轰炸。

### 6.2 长期阶段

- 阶段截止前 24 小时提醒一次。
- 阶段截止时提醒一次。
- 长期任务的目标日仍参与普通 24h/3h/30min 提醒。

### 6.3 每日简报（可选）

- 到设定时间后 2 小时内检查一次，每天最多一条。
- 内容：今天有几件事、其中几件已逾期。

### 6.4 能力边界（重要）

这是 Web/PWA 的固有限制，不是文案可以掩盖的：

- 页面或已安装 PWA 存活时，提醒最可靠。
- 浏览器完全退出后，纯前端无法保证定时唤醒；iOS 对后台网页限制更严格。
- 因此 MVP 的“系统通知”是**尽力而为**；需要 100% 准时，应进入 Phase 4，用 Capacitor 封装原生本地通知。详见《技术方案》。

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 移动优先 | 360–480px 宽度为设计基准；安全区适配；底部导航单手可达 |
| 性能 | 首屏 JS 总量 < 100KB（未压缩，无第三方库）；任务量 1000 条内交互流畅 |
| 离线 | Service Worker 缓存应用外壳；无网络可打开与增删改查 |
| 隐私 | 无账号、无埋点、无业务请求；数据只在本机 localStorage |
| 可访问性 | 触控目标 ≥ 40px；颜色 + 图标 + 文字三重区分；支持减少动效；表单有 label |
| 兼容 | iOS Safari 16.4+、Android Chrome/Edge 现代版本；不支持的系统通知会降级为应用内提醒 |
| 数据安全 | 导出/导入有确认；删除有确认；存储损坏有备份 |
| 文案 | 中文、短句、说人话；不使用“暂无数据”这类后台语言 |

## 9. MVP 成功指标（本地可观察）

因为无后台、无埋点，MVP 只定义可离线验证的产品指标：

1. **首次创建成功率**：新用户首次输入一句话后，无需手动补标题即可保存。
2. **解析接受率**：保存前没有修改任何解析字段的比例（通过本地调试可统计，不作为正式埋点）。
3. **回访行为**：用户第二天再次打开，且今日页有任务。
4. **提醒触达**：开启通知的用户中，出现过至少一次提醒。
5. **完成行为**：创建后 7 天内至少完成 1 个任务。

> 正式上线若需要真实指标，必须新增加隐私友好的本地统计/可选上报，并单独做隐私评审，不在本次 MVP 范围。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 中文时间表达极其多样 | 解析错误、用户不信任 | 规则解析 + 明确展示识别结果 + 全字段可改；不追求 100% |
| Web 通知不能唤醒已关闭浏览器 | 漏提醒 | 明确说明；引导安装到主屏幕；Phase 4 原生封装 |
| localStorage 容量约 5MB | 大量任务/备注可能写满 | 限制备注 2000 字、标签 8 个；写入失败提示导出；后续迁移 IndexedDB |
| 示例数据被误认为真实任务 | 困惑 | 明显的示例横幅，一键清空；设置里可重新载入 |
| 定期任务反复生成导致堆积 | 列表膨胀 | 完成后才生成下一次；恢复时撤回自动生成的下一次；逾期完成跳到下一个未来时间 |
| 用户手动改字段后又被自动解析覆盖 | 挫败 | 手动修改后停止自动解析；只有改原话或点“重新识别”才重新解析 |
